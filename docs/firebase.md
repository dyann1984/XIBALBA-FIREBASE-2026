# Configuración de Firebase y límites

La integración usa Firebase AI Logic con Gemini Developer API y modo PREFER_ON_DEVICE; el respaldo configurado es gemini-3.5-flash-lite. El origen se muestra únicamente después de una respuesta real. La disponibilidad local es una consulta orientativa a la Prompt API de Chrome y no garantiza que el modelo esté listo. La descarga del modelo se inicia en la interacción del usuario; el SDK puede usar nube mientras no esté listo. La función requiere consentimiento explícito para el posible envío a la nube. Las URL se analizan como texto; no se visitan ni verifican contra listas de amenazas.

1. Con Node 24.12 o superior, ejecuta `npm install`. Copia `.env.example` a `.env.local` y agrega la configuración web de tu proyecto Firebase y la clave de sitio reCAPTCHA Enterprise. Son identificadores de configuración de cliente; no agregar claves privadas ni claves directas de Gemini.
2. En la consola Firebase, habilita AI Logic con Gemini Developer API, registra la aplicación web y configura App Check con reCAPTCHA Enterprise. Aplica App Check a Firebase AI Logic. Revisar cuotas y costos antes de habilitar servicios; no activar facturación automáticamente.
3. Para desarrollo local, crea manualmente un token en Firebase Console → App Check → aplicación web → menú de tres puntos → Administrar tokens de depuración. Copia el valor nuevo directamente a `FIREBASE_APP_CHECK_DEBUG_TOKEN` en `.env.local` y establece `NEXT_PUBLIC_FIREBASE_APP_CHECK_DEBUG=true`. Reinicia `next dev` vinculado exclusivamente a localhost y abre `/diagnostico-app-check`; el botón comprueba el intercambio sin mostrar el valor. La variable sin prefijo NEXT_PUBLIC se lee solo en el servidor, pero el proveedor web necesita enviar el valor al navegador: es visible en sus herramientas de desarrollo y el SDK puede imprimirlo en la consola. Evita capturas y compartir registros; no incluyas el token en Git. Revoca los tokens expuestos en Firebase. Desactiva el modo estableciendo la variable pública en `false` y reinicia el servidor. No autorices localhost como dominio de reCAPTCHA. Producción requiere la clave real de sitio de reCAPTCHA Enterprise.
4. Firestore está preparado con reglas que deniegan todas las lecturas y escrituras; no hay persistencia de mensajes. Las reglas deben desplegarse y probarse en el proyecto Firebase antes de confiar en ellas. No hay historial funcional todavía.
5. Reinicia el servidor al cambiar variables. Ejecuta un análisis con contenido ficticio y verifica el resultado y el origen. Hasta entonces la conexión no está verificada.

Las respuestas de IA pueden ser incorrectas o manipuladas por el texto de entrada; validar evidencias y no considerarlas confirmaciones. El control de cuota del cliente no sustituye cuotas y protección del servicio. No se solicita ni se usan accesos a redes sociales o llamadas.
